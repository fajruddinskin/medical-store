# Medical Store — Project Documentation

This document summarizes the Medical Store Management System in this repository. It covers project purpose, tech stack, configuration, database schema, key endpoints and controllers, home page features, build/run instructions, and useful notes for contributors.

---

## Project Overview

Medical Store is a Spring Boot web application to manage medicines, customers, patients, lab tests, and lab reports. It includes a Thymeleaf-based UI plus a set of RESTful APIs for CRUD operations and report management. The application uses SQLite as its embedded datastore.

Key features:
- Medicine inventory management (search, low-stock, expired, prescriptions)
- Customer/user management
- Patient records and lab test registration
- Lab test catalog and lab reports with templates
- REST APIs and HTML pages (Thymeleaf)

---

## Tech Stack
- Java 17
- Spring Boot 3.2.0
- Spring MVC, Spring Data JPA, Spring Security
- SQLite (via org.xerial:sqlite-jdbc)
- Thymeleaf for server-side HTML templates
- Maven (wrapper included)

## Configuration
- Java version: 17 (see `pom.xml`)
- Spring profile / server port: configured in `application.properties`:
  - `server.port=8081`
  - `spring.datasource.url=jdbc:sqlite:./data/medical_store.db`
  - `spring.jpa.hibernate.ddl-auto=update` (the project also ships `schema.sql`)
- Additional base metadata is in `src/main/resources/base.properties` (store name, address, contact)

The main application class `MedicalStoreApplication` ensures the `data/` directory is created on startup and attempts to open the browser at `http://localhost:8081` after the server starts.

## Database (schema summary)
The schema is in `src/main/resources/schema.sql`. Key tables:
- `medicines` — medicine records (id, name, batch_number, price, quantity, manufacture_date, expiry_date, manufacturer, type, requires_prescription, category_id)
- `categories` — category definitions (id, name, description)
- `users`, `admins`, `customers` — user/customer/admin records and relationships
- `patients` — patient-specific data (referencing customers by id)
- `tests`, `tests_data` (and `tests_data` used by lab test templates) — lab test catalog / template data
- `report_containers`, `report_tests`, `report_results` — lab test containers (a report that aggregates tests), many-to-many link table, and stored report HTML

Seed/sample data is provided in `src/main/resources/data.sql` (categories, medicines, sample users, tests, report containers, and a sample report content).

## Main Controllers & Endpoints
The REST endpoints are implemented in the `com.medicalstore.controller` package. Below are the important controllers and the main endpoints they expose.

### MedicineController (`/api/medicines`)
- GET `/api/medicines` — list all medicines
- POST `/api/medicines` — create medicine
- GET `/api/medicines/{id}` — get by id
- PUT `/api/medicines/{id}` — update medicine
- GET `/api/medicines/search?searchTerm=...` — search medicines
- DELETE `/api/medicines/delete/{id}` — delete (returns JSON success/message)
- GET `/api/medicines/low-stock` — low stock medicines
- GET `/api/medicines/type/{type}` — by type
- GET `/api/medicines/manufacturer/{manufacturer}` — by manufacturer
- GET `/api/medicines/expired` — expired medicines
- GET `/api/medicines/prescription` — requires prescription

### UserController / Customer APIs (`/api/customers`)
- GET `/api/customers` — list customers
- POST `/api/customers` — create customer
- GET `/api/customers/{id}` — get by id
- PUT `/api/customers/{id}` — update (via CustomerModel)
- DELETE `/api/customers/{id}` — delete
- GET `/api/customers/search?name=...` — search by name
- GET `/api/customers/phone/{phoneNumber}` — find by phone

### CategoryController (`/api/categories`)
- GET `/api/categories` — list
- POST `/api/categories` — create
- GET `/api/categories/{id}` — get
- DELETE `/api/categories/{id}` — delete

### LabTestController (`/api/lab-tests`)
- GET `/api/lab-tests/{id}` — get test data by id
- PUT `/api/lab-tests/{id}` — update test data
- GET `/api/lab-tests/find?searchTerm=...` — search lab test data
- GET `/api/lab-tests/search?searchTerm=...` — search tests (another endpoint used in different contexts)
- POST `/api/lab-tests` — create lab test model

### LabReportController (`/api` prefixed endpoints)
- POST `/api/delivery/add` — set delivery date for a container
- POST `/api/discount/add` — apply discount to a container
- DELETE `/api/delete/{containerId}/{testId}` — remove a test from container
- GET `/api/print/{id}` — get container for printing
- POST `/api/add-test/{id}` — add a lab test to a container (creates a test instance and attaches report template)
- GET `/api/search?searchTerm=...` — search lab-test containers / tests
- POST `/api/save-report` — save HTML report content and set status (PENDING/IN_PROGRESS/DONE)

### SqlController (`/api/sql/execute`)
- POST `/api/sql/execute` — execute arbitrary SQL payload (use carefully — intended for admin/debug)

### PatientController (`/api/patients`)
- POST `/api/patients` — create patient record
- POST `/api/patients/create/{id}` — create patient and attach to an existing report container; also fills template placeholders in the report

### AuthController & WebController
Handle server-side pages (Thymeleaf views): `/`, `/dashboard`, `/medicines`, `/customers`, `/reports`, `/lab-test-registration`, `/signup`, `/login`, `/admin` etc.

---

## Notable Services and Behaviour
- `LabReportController` uses `containerCalculationService` to recalculate totals (subtotal, total) when tests are added/removed or when discounts are applied.
- `PatientController#createPatient1` replaces placeholder tokens like `patientData`, `ageData`, `sexData`, `todayDate` inside stored report HTML before persisting.
- `SqlController` allows executing arbitrary SQL — this is powerful and a potential security risk; restrict or remove in production.

### Search Functionality
Users can search lab tests by entering a search term in the search input field. The search feature displays results in a dedicated **Search Results** table at the top of the page.

#### Default State (No Search)
When the page first loads or if the search field is empty, the Search Results table displays a placeholder message:
- **Columns:** Id, Name, Price, Action
- **Message:** "Enter a search term to view results" with a search icon

#### After Search is Performed
When a user enters a search term and presses Enter or triggers the search, the table populates with matching lab tests:

| Column | Description |
|--------|-------------|
| **Id** | Unique identifier of the lab test |
| **Name** | Name of the lab test |
| **Price** | Price of the lab test (formatted as currency, e.g., $100.00) |
| **Action** | Action buttons for Edit and Delete operations |

**Action Buttons:**
- **Edit** - Opens a modal dialog to edit the lab test details (Name, Description, Price, Referrer Fee)
- **Delete** - Removes the lab test after user confirmation

#### Search Results Display
- If no results are found, displays: "No lab tests found." with an inbox icon
- If an error occurs during search, displays: "Error fetching lab tests." with an alert icon
- Maximum results are returned from the `/api/lab-tests/find` endpoint with the search term parameter

#### Search Endpoint
- **API Endpoint:** `GET /api/lab-tests/find?searchTerm={searchTerm}`
- **Returns:** List of `LabTestData` objects matching the search term
- **Data Attributes Returned:** id, name, description, price, referrerFee

### Data Flow
1. User visits `http://localhost:8081/`
2. `WebController.index()` fetches all lab tests from the database
3. Selects the last 5 lab tests (or all if less than 5)
4. Passes `recentLabTestData` to the Thymeleaf template
5. Template renders the table with:
   - **Id** - Lab test ID
   - **Name** - Lab test name
   - **Action** - Edit and Delete buttons

### User Interactions

**Edit Lab Test:**
- Click the "Edit" button on any row
- The Edit Lab Test Modal opens
- Modal is pre-populated with the selected test's data:
  - Name
  - Description
  - Price
  - Referrer Fee
- User can modify any field
- Click "Update" to save changes
- Click "Cancel" to discard changes

**Delete Lab Test:**
- Click the "Delete" button on any row
- A JavaScript confirmation dialog appears asking "Are you sure you want to delete this lab test?"
- If confirmed:
  - The lab test is deleted from the database
  - The table row is immediately removed from the view
  - A success message is displayed
- If cancelled, the delete operation is aborted

### JavaScript Functions in index.html

**Search Functionality:**
```javascript
$(document).ready(function() {
    $('#searchInput').on('keypress', function(e) {
        if (e.which === 13) { // Enter key
            performSearch();
        }
    });

    function performSearch() {
        let query = $('#searchInput').val().trim();
        if (query === "") {
            // Reset to default placeholder state
            $('#searchResults').html(
                '<tr><td colspan="4" class="text-center text-muted py-3">' +
                '<i class="fas fa-search fa-2x mb-2"></i><br>' +
                'Enter a search term to view results</td></tr>'
            );
            return;
        }

        $.ajax({
            url: '/api/lab-tests/find',
            type: 'GET',
            data: { searchTerm: query },
            success: function(data) {
                // Renders table with columns: Id, Name, Price, Action
                // Price is formatted as currency (e.g., $100.00)
                // Edit and Delete buttons are displayed for each result
                let html = '';
                if (data.length === 0) {
                    html = '<tr><td colspan="4" class="text-center text-danger py-3">' +
                           '<i class="fas fa-inbox fa-2x mb-2"></i><br>' +
                           'No lab tests found.</td></tr>';
                } else {
                    data.forEach(lab => {
                        html += `<tr data-id="${lab.id}">
                                <td>${lab.id}</td>
                                <td>${lab.name}</td>
                                <td>$${parseFloat(lab.price).toFixed(2)}</td>
                                <td>
                                    <button type="button" class="btn btn-sm btn-primary edit-btn"...>
                                        <i class="fas fa-edit"></i> Edit
                                    </button>
                                    <button type="button" class="btn btn-sm btn-danger delete-lab-btn"...>
                                        <i class="fas fa-trash"></i> Delete
                                    </button>
                                </td>
                            </tr>`;
                    });
                }
                $('#searchResults').html(html);
            },
            error: function() {
                $('#searchResults').html(
                    '<tr><td colspan="4" class="text-center text-danger py-3">' +
                    '<i class="fas fa-exclamation-triangle fa-2x mb-2"></i><br>' +
                    'Error fetching lab tests.</td></tr>'
                );
            }
        });
    }
});
```

## Admin SQL Console (Enhanced SQL Editor)

The Admin SQL Console is available at [`http://localhost:8081/admin`](http://localhost:8081/admin). It provides a powerful web-based SQL editor for database administration and debugging.

### Features
- **SQL Editor:** Enter and execute any SQL statement (SELECT, INSERT, UPDATE, DELETE, etc.) directly from the browser.
- **Result Display:**
  - SELECT queries: Results are shown in a dynamic table with column headers and data rows.
  - Data modification queries (INSERT, UPDATE, DELETE): Shows the number of affected rows.
  - Error handling: Displays error messages for invalid SQL or execution failures.
- **UI/UX:**
  - Modern Bootstrap-based card layout
  - Syntax-highlighted textarea for SQL input
  - Responsive design for desktop and mobile
  - Clear and Execute buttons for workflow efficiency
- **Security:**
  - **Warning:** This feature allows execution of arbitrary SQL. It is intended for admin/debug use only. Ensure this endpoint is protected and never exposed in production environments.

### API Endpoint
- `POST /api/sql/execute` — Accepts a JSON payload `{ "sql": "..." }` and returns query results or modification status.

### Example Usage
- Run a SELECT query:
  ```sql
  SELECT * FROM users;
  ```
- Insert a new record:
  ```sql
  INSERT INTO medicines (name, price) VALUES ('Aspirin', 10.50);
  ```
- Update a record:
  ```sql
  UPDATE users SET enabled = 1 WHERE id = 2;
  ```
- Delete a record:
  ```sql
  DELETE FROM users WHERE id = 3;
  ```

### How it Works
1. Enter your SQL statement in the editor and click **Execute Query**.
2. The backend executes the SQL and returns the result.
3. SELECT results are shown in a table; modification queries show affected row count.
4. Errors are displayed in a user-friendly alert.
